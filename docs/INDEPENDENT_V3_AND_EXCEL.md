# Независимая 3.0 и Excel-матрицы

Решение владельца: 2026-10-26. Приоритет над прежними требованиями переноса из 2.0.

## Продуктовый контракт

- 3.0: отдельный Android package `com.fitcoach.v3`, название «Дневник атлета».
  2.0 остаётся `com.fitcoach.app`. Старые внутренние dev package не являются release identity.
- `.atbackup` — полная копия собственного состояния 3.0: SQLite всех владельцев,
  настройки тренера, фото рецептов и журнал повторных Excel-импортов. Восстановление
  заменяет состояние целиком; страховочная точка позволяет однократный возврат.
  Папки назначения копий, Android SAF grants, журналы текущей операции и сами внешние
  копии являются состоянием устройства и не переносятся как данные клиента.
- Никакой поддержки бэкапа 2.0 в 3.0. Прямое чтение её базы не входит в запуск приложения;
  старый автоматический dev-import также отключён.
- Через Excel переносим планы и фактические результаты тренировок. Питание, замеры,
  оплаты и записи календаря 2.0 не входят в перенос. Даты тренировок не создают записи календаря.
- Экспорт — одна книга на клиента с выбранными программами. Видимые листы — матрицы:
  упражнения/подходы по строкам, недели по столбцам. В неделе: План, Пред., Повт., Кг,
  Дата. Сек/М видны при наличии этих показателей. Каждый мезоцикл получает свой лист.
  По уточнению владельца экспорт — только слепок видимой матрицы, без скрытых листов,
  столбцов, внутренних ID и добавления упражнений или подходов из старой истории.
- Вес видимых листов — килограммы. План вида `8–10 × 62,5 кг`; время и расстояние
  можно добавить как `× 60 с × 100 м`. Ноль веса сохраняется, отсутствие остаётся пустым.
- «Пред.» вычисляется по подтверждённым фактам предыдущей недели. При импорте
  содержимое этой колонки не создаёт и не заменяет фактов.
- Старые версии и результаты удалённых строк остаются внутри приложения и полного
  `.atbackup`, но не добавляются в пользовательский Excel. В 2.0 экспорт не читает
  канонические исторические упражнения для дополнения текущей матрицы.
- Служебные названия вида `exercise_UUID` не экспортируются и отбрасываются при чтении
  старой плоской матрицы. Названия по ID не угадываются. Старый формат со скрытой
  структурой остаётся читаемым для совместимости, но больше не выдаётся пользователю.
- Правки плана, повторов, веса и дат существующих ячеек матрицы читаются обратно.
  Строки/столбцы экспортированной книги сохраняются; для создания произвольной новой
  программы доступен отдельный свободно заполняемый матричный шаблон.
- Старые плоские шаблоны и матрицы 2.0 проходят отдельный адаптер. Пользователь
  выбирает лист и столбцы. Неизвестные упражнения нужно сопоставить либо явно создать,
  выбрав категорию и профиль измерений.
- Импорт: файл → клиент (существующий или новый) → предварительный просмотр →
  сопоставление → подтверждение → одна транзакция планов, истории и фактов. Ошибка
  откатывает весь пакет. Повтор нового формата пропускается; изменение исходной или
  локальной программы даёт конфликт без автоматической перезаписи.
- Неизвестная дата в Excel обозначается «неизвестно», не заменяется датой импорта.
  Такой план открывается в конструкторе. Для переноса фактических результатов через
  полный импорт текущая схема 3.0 требует реальные даты. Поддерживаются текстовые дни
  YYYY-MM-DD/ДД.ММ.ГГГГ и даты Excel 1900/1904. Формулы в импортируемых файлах отклоняются.
- Некорректные старые значения не превращаются в нули или произвольную границу диапазона.
  Лист «Проверить значения» сохраняет исходный текст, программу, тренировку и подход.
  До явного исправления импорт блокируется. Разрешены число, «пусто» и удаление
  ошибочного фактического подхода; корректные результаты автоматически не удаляются.
- Сохранённые занятия удалённых мезоциклов и программ также доступны для экспорта 2.0.
  Если текущего плана уже нет, переносится история с указанием её происхождения.

## Интерфейсы и реализация

- Общий DTO `TrainingTransfer` не зависит от схемы 2.0. Версия формата — 1.
  `TrainingTransferPort` экспортирует выбранные программы и атомарно импортирует пакет.
- Владелец планов читает/пишет структуру и её версии; владелец выполнений — факты,
  даты, заметки, стороны и мини-сеты. UI не выполняет SQL.
- `training-transfer` — отдельный владелец журнала импортов. Его схема включена в
  инвентарь бэкапа; контрольные суммы учитывают исходную и текущую локальную программу.
- Изоляция импорта при восстановлении обеспечивается общим RuntimeCommandGate.
- Код формата синхронизируется в отдельную ветку 2.0 командой `npm run excel:sync-v2`.
  Библиотека: SheetJS CE 0.20.3, Apache-2.0, та же зафиксированная версия, что в 2.0.
  Основание: https://docs.sheetjs.com/docs/demos/mobile/reactnative/ и
  https://docs.sheetjs.com/docs/getting-started/installation/frameworks/ .
- Путь в UI 3.0: Настройки → Резервные копии → Импорт и экспорт Excel;
  также Создать программу → Импортировать из Excel.

## Уточнение владельца: импорт внутри конструктора

При создании простой программы, расширенной программы или нового мезоцикла кнопка
«Импортировать Excel» находится в конструкторе. Путь: файл → лист → сверка карточек
тренировок и упражнений через общий каталог → применение к черновику → обычное
редактирование и сохранение. У старых таблиц сохраняется настройка столбцов.
Неоднозначные совпадения требуют выбора; неизвестные упражнения можно создать.
Применение листа заменяет черновик после подтверждения, а не создаёт другую программу.
Публикация происходит штатной командой конструктора; история результатов переносится
отдельным полным импортом через настройки. В простой конструктор нельзя без потерь
применить различающиеся недельные планы: предлагается использовать расширенную программу.

Проверки проекции листа охватывают новые ID, сохранение родства и значений недель,
отсутствие изменений исходной истории и запрет потери недельных различий.

В списке программ меню «⋮» каждой карточки содержит «Экспорт в Excel»,
«Архивировать», «Удалить». Экспортируется вся программа со всеми циклами и историей.
Внутри расширенной программы меню рядом с «Изменить» и «В шаблоны» содержит
«Экспорт цикла в Excel»: только выбранный цикл, его исторические версии и результаты.
Отбор — по ID цикла и слотов тренировок, не по названиям и датам. Если принадлежность
части истории к циклам установить нельзя, предлагается экспортировать программу целиком.
Архивирование и удаление используют существующие команды владельцев данных;
удаление требует явного подтверждения и действует только у текущего клиента.

Уточнение меню владельцем: из «⋮» рядом с «Изменить» / «В шаблоны» убраны
перестановка и копирование недель, а также повторное сохранение мезоцикла как шаблона.
Видимая кнопка «В шаблоны» сохраняет текущий цикл; пункт «Всю программу в шаблоны»
в меню сохраняет всю книгу. У простой программы видимая кнопка уже сохраняет всю
программу, поэтому дополнительного пункта в меню нет.

На телефоне в синтетической QA-карточке прошли импорт листа в новую расширенную
программу, замена через каталог и импорт листа в новый цикл существующей программы.
Экспорт из меню карточки сохранён и прочитан: одна программа, два цикла по две недели.
Отдельный экспорт из меню внутри программы содержит один цикл; все его плановые
значения совпали с соответствующим циклом полной книги. Личные данные не изменялись.

Последний проверенный на устройстве кандидат 3.0 — build5: новый значок владельца сохранён,
сертификат совпадает с предыдущими отдельными 3.0, данные при обновлении сохранены.

Исправление слепка матрицы: кандидаты 3.0 build8 и 2.0 build133. Host Excel 32/32
и 11/11 соответственно. На приватной копии 25 клиентов сформированы 65 листов без
скрытых данных и внутренних названий. Для 62 текущих матриц названия строк и 47 626
ячеек повторений/веса совпали со штатной моделью матрицы 2.0. Пользовательские файлы
и подробности сверки остаются вне Git. Это проверка слепка, а не прежней выгрузки всей истории.

Уточнения интерфейса build8: «Дополнительно → Импортировать из Excel» сразу открывает
выбор файла в контексте текущего клиента, затем лист и сверку. Полный импорт использует
существующий владелец данных; кнопки внутри конструкторов применяют только план к черновику.
В разделе данных оставлены только резервные копии. «Панель навигации» доступна только
в настройках списка и карточек клиентов. Имена Excel содержат ФИО клиента и программу,
при единственном цикле — также цикл. У бэкапов свой прежний формат имён.

При холодном запуске добавлена короткая анимация значка и названия; данные готовятся
параллельно. Ошибки загрузки/восстановления не скрываются; системное уменьшение движения
учитывается. Подключены 18 готовых SVG оборудования из коллекции владельца. Для 42
ссылок оригиналы недоступны (HTTP 403); их прежние иконки сохранены.

Решение владельца — P01-INDEPENDENT-PARTICIPANTS (2026-10-26).
Группа содержит отдельные ссылки на независимые циклы клиентов; один цикл принадлежит
одной группе. Добавление: копия текущего плана в выбранную или новую программу либо
существующий цикл через нажатие на пилюлю. Перенос из другой группы подтверждается явно.
Связь не меняет ID, родство, планы и факты существующего цикла. Все правки индивидуальны.
Переключение использует точный номер недели и порядковый номер тренировки. Отсутствующая
позиция скрывает участника в дневнике. Архивация программы временно скрывает участника,
восстановление возвращает его; связь с группой сохраняется.
Ввод сохраняется до перехода. Миграция добавляет только связи; прежние активные группы
копий переносятся после проверки уникальности клиентов. Бэкап включает связи;
Excel остаётся видимым слепком без технических ID и групп.
Входы: конструктор и дневник. Зависимости: владелец plans, SQLite writer, полный backup.
Product refs: §48.6, §48.28 с данным явным решением владельца в качестве override.
Проверки миграции, отката, ID и бэкапа пройдены; Android smoke выполнен на build9.
Build10 собран для самостоятельной установки владельцем. Подробности:
`docs/PARTICIPANT_GROUPS_VALIDATION.md`.

Решение владельца — I02-EXCEL-REVIEW (2026-10-26): после выбора Excel открывается
сверка в конструкторе с горизонтальными вкладками листов в порядке книги.
Импортируется только открытый лист; сопоставления, исправления и настройки каждого
листа сохраняются до закрытия файла. Ручные настройки находятся в раскрываемом
разделе «Настроить столбцы»: поля в две колонки, выбор столбца выпадающим списком,
подпись строки заголовков и фрагмент исходной таблицы. У матриц приложения показана
исходная матрица и пояснение об автоматическом распознавании, а не техническая
развёртка для внутреннего адаптера.

Спорное фактическое значение, включая диапазон «8-10», открывается для ручной
проверки с координатой исходной ячейки. Разрешены явное исправление числом или
«Оставить пустым». Числа не угадываются; нерешённые значения блокируют полный
импорт, а полностью пустые подходы не подтверждаются автоматически. Импорт плана
в черновик конструктора не переносит фактические результаты и не блокируется ими.
Неизвестные даты по-прежнему не становятся сегодняшними. Изменения схемы БД нет.
Входы: XLSX и интерфейс сверки. Зависимости: Excel-адаптер, модель TransferIssue,
команды владельцев данных. Product refs: дополнение владельца и утверждённый план
«Исправление импорта Excel». Gates: профильные тесты, реальная выгрузка, типы,
источники и Android APK. Установка APK на телефон исключена по просьбе владельца.

I03-EXCEL-TRIGGER: по уточнению владельца меняется только внешний вид кнопки
«Импортировать из Excel» в разделе «Дополнительно» выбора программы. Используется
прежняя FeatureRow, как у «Создать из шаблона»: иконка, подпись, пояснение и стрелка.
Команда выбора файла сохраняется; разбор и сверка Excel остаются как в build11.

I04-IMPORT-CATALOG — утверждённое решение владельца 2026-10-26:
возврат из каталога внутри импорта сначала закрывает фильтр, затем возвращает к
сверке. Список существующего оборудования не сокращается по мышцам, режиму или
запросу упражнений; добавляется отдельный поиск в фильтре и редакторе упражнения.
«Бабочка» — поисковый синоним существующего пек-дека, не новое оборудование.

Ручной выбор или создание упражнения применяется ко всем точным исходным
названиям во всех листах текущей книги. Регистр, «е/ё», пунктуация и внутренние
пробелы различаются; пробелы по краям удаляются существующим адаптером.
Сохранённые циклы и результаты не редактируются. Сопоставления запоминаются
в рабочем пространстве тренера после успешного импорта или применения черновика.
При следующем открытии книги предлагается общий список с возможностью исключить
отдельные пары. До подтверждения эти пары не подставляются. Недоступные упражнения
требуют ручного выбора. Текущий ручной выбор приоритетнее исторического.

Владелец training-transfer добавляет отдельную таблицу сопоставлений миграцией v2.
Она включается в собственный бэкап 3.0 и не попадает в Excel. Полный импорт и
сохранение новых пар выполняются одной транзакцией. Зависимости: Exercise Registry,
WorkbookReviewSession и training-transfer; Product refs: §31, §39 с данным явным
решением владельца. Gates до APK: синтетические миграции/откат, бэкап, профильные
тесты, типы, источники и Android-сборка. Установка на телефон исключена.

I05-WHOLE-WORKBOOK — уточнение владельца, заменяющее правило I02 об импорте
открытого листа: одна книга Excel становится одной программой, каждый непустой
лист — отдельным циклом в порядке книги. Вкладки переключают только сверку.
Кнопка «Импортировать всю книгу» проверяет все листы и сохраняет программу,
циклы, результаты и новые сопоставления одной транзакцией. Нерешённая ошибка
любого листа блокирует всю запись; список указывает, какие листы проверить.
Пустые листы явно перечисляются и пропускаются. Название программы можно изменить.
Прежние частичные импорты не дополняются и не перезаписываются автоматически.
Загрузка плана в уже открытый черновик одного цикла остаётся явно отдельным
действием с выбранным листом; полный импорт программы находится в карточке клиента.
Входы: уточнение владельца и текущая сверка книги. Зависимости: I04, существующая
транзакция владельцев планов/результатов. Новая схема БД не требуется.
Gates: несколько циклов/результатов, ошибка неактивного листа, откат, повторный
импорт, типы, lint, границы модулей, источники и Android APK без установки.

I06-IMPORT-COMPLETION-RENAME — уточнение владельца: полный импорт Excel завершает
все тренировки всех циклов книги, в том числе без фактических результатов.
Пустые подходы остаются пустыми, подтверждения результатов не выдумываются.
Неизвестные даты, время начала и окончания не заменяются моментом импорта.
Для этого execution v3 допускает actual_date = NULL; транзакционная миграция
сохраняет строки, ID, связи и защитные триггеры. Источник и импортируемые данные
изменяются только в предварительном просмотре; прежние импорты не переписываются.
Правило I02/I05 об обязательном заполнении неизвестной даты для полного импорта
заменено сохранением неизвестной даты. Проверки формата известных дат сохраняются.
В меню карточки самой программы добавляется «Переименовать программу» через
существующую команду renameProgram. Названия циклов и тренировочные данные не меняются.
Входы: два уточнения владельца; зависимости: I05, execution и планы; Product refs:
исходы тренировок §48.31 и явное разрешение владельца закрывать все импортируемые слоты.
Gates: миграция с заполненными дочерними таблицами/откат, статусы пустых слотов,
бэкап/восстановление, повторный импорт, переименование без изменения фактов,
профильные тесты, типы, lint, источники и Android-сборка без установки на телефон.

I07-WORKBOOK-DRAFTS — план владельца от 2026-10-27:
область импорта задаётся явным списком листов с галочками, по умолчанию выбраны все
непустые листы. Открытая вкладка управляет только сверкой. Исключение листа сохраняет
его настройки и исправления; ошибки исключённого листа не мешают выбранным.
Перед записью показываются целевая программа, названия листов и количество циклов.

В конструкторе выбранные листы добавляются циклами текущего черновика. Заполненный
цикл сохраняется; пустой стартовый заменяется. Переход из простого конструктора
подтверждается и переносит работу в расширенный черновик, не перезаписывая уже
существующий расширенный черновик. Конструктор переключает циклы, сохраняя их
настройки и выбранные недели. Общая кнопка сохраняет планы, факты, сопоставления,
журнал импорта и очистку recovery-черновика одной транзакцией. Другим участникам
копируются только планы. Повторное добавление листа в ту же программу пропускается;
правки сохранённого импортированного цикла вызывают конфликт без перезаписи.

В импорте один основной Modal: список листов, история сопоставлений, сверка и
подтверждение являются его внутренними страницами. Монтируется только открытая
сверка. Подготовка листов уступает управление интерфейсу, отмена инвалидирует
запоздавшие ответы; повторный запуск записи блокируется до окончания транзакции.

Выход из конструктора с черновиком предлагает сохранение, удаление или продолжение
работы. Очередь автосохранения завершается перед сохранением; удаление отменяет
ожидающие записи и не позволяет unmount восстановить удалённую работу. При создании
программы доступны продолжение существующих черновиков и начало новой. Старый
черновик выбранного типа удаляется только с подтверждением. Аварийное автосохранение
и старые одноцикловые recovery-данные поддерживаются.

Миграция plans v4 расширяет защиту JSON recovery-данных, transfer v3 добавляет
необязательную связь квитанции с циклом. Старые строки и ID не меняются; новые
постоянные таблицы не добавляются. Бэкап включает recovery-данные и журнал импорта.
Входы: утверждённый план I07; зависимости: I06, владельцы планов и выполнений;
Product refs: §48.29 и уточнения владельца. Gates: выбор листов, экранные повторы,
транзакционный откат, restore/discard, миграции/бэкап, типы/lint/источники и APK.
Установка на телефон не выполняется по сохранённому указанию владельца.
