# Переходный выпуск для переноса 2.0 → 3.x

> **Отменено владельцем 2026-10-26/27.** Прямая миграция 2.0 → 3.0 и установка поверх 2.0 больше не
> планируются, код удалён (R04-RETIRE). Действует `../INDEPENDENT_V3_AND_EXCEL.md`: отдельная 3.0 и перенос
> тренировок через Excel. Текст ниже — только история.

Решение владельца от 2026-10-23: выпустить версию с переносом данных 2.0,
после неё убрать ненужный код поддержки 2.0 из следующей версии.
Это два последовательных выпуска «Дневника атлета». Реализация и выпуск
пока не завершены; migration, signing, overlay и release gates остаются OPEN.

## Переходный выпуск (рабочее обозначение 3.0)

- Читает поддерживаемую резервную копию 2.0 отдельным импортёром.
- Проверяет источник, переносит все поддерживаемые данные в staging 3.x,
  сохраняет устойчивые ID, происхождение и точность значений, сверяет parity.
- До успешного завершения не меняет исходник и рабочие данные. Прерывание,
  повтор и восстановление проверяются на Android в рамках общих gates.
- После переноса работает с моделью 3.x и создаёт самодостаточную копию 3.x.
  Для открытия этих данных больше не требуется старый источник или повторный
  запуск преобразования из 2.0.
- При выпуске сохраняются исходный commit/tag, подписанная сборка, контрольная
  сумма и инструкция переноса. Они нужны пользователям, которые обновятся позже.
  Это будущие артефакты; их наличие сейчас не заявляется.

## Следующий обычный выпуск 3.x

- Обновляет переходный выпуск и открывает его данные и резервные копии 3.x.
- Не содержит чтение SQLite/JSON 2.0, сопоставление старых таблиц и полей,
  восстановление старых представлений или экран прямого импорта 2.0.
- Пользователь, оставшийся на 2.0, сначала переносит данные переходным выпуском,
  затем обновляется. Прямой импорт 2.0 в обычном выпуске не обещается.
- Парсеры и преобразования 2.0 должны иметь отдельную точку подключения.
  Сборку обычного выпуска проверяют на отсутствие зависимостей от импортёра,
  а не ограничиваются скрытием кнопки.

## Что сохраняется после удаления импортёра

Данные уже перенесённого пользователя принадлежат формату 3.x. Неизвестная дата,
историческое название упражнения, тип подхода, заметка, происхождение и ID факта
не становятся ненужными после завершения импорта. Их хранение, отображение,
редактирование по правилам 3.x и резервное копирование остаются. Код обычной
копии/восстановления 3.x, проверка целостности и атомарная замена базы также остаются.

Удалять импортёр можно после проверки полного пути: копия 2.0 → переходный
выпуск → данные и копия 3.x → следующий выпуск без импортёра. Проверка должна
подтвердить сохранность фактов, значений, связей, владельцев и ID, включая записи
без даты. Наличие копии 3.x не считается доказательством её восстановимости.

Эта последовательность не разрешает удаление приложения 2.0, работу на единственной
пользовательской базе или обход проверки совместимости подписи Android.
Точный способ установки остаётся предметом открытых gates.
