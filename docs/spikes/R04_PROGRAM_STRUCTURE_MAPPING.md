# R04 — исходная структура программ 2.0

Статус: PARTIAL, read-only graph и проверка связей. Целевые записи и schema
migrations не создаются. Это продолжение проверки program/book identity.

## Входы и требования

Задача R04, зависимость R03. Product §§48.1–48.5.7, 49–50, Feature 09/18:
сохранение фактов, provenance и независимости назначений клиентов. Одинаковый
book ID не означает общую историю участников или готовую программу 3.x.

Read-only reference build120, commit `e116b42e95f70a5a5e563420ab25394944c59ffd`:
[структурные таблицы](https://github.com/Hwan-Karasu/fitcoach/blob/e116b42e95f70a5a5e563420ab25394944c59ffd/apps/mobile/src/shared/db/migrations/001_initial.ts),
[библиотека программ](https://github.com/Hwan-Karasu/fitcoach/blob/e116b42e95f70a5a5e563420ab25394944c59ffd/apps/mobile/src/shared/db/migrations/025_program_library.ts).

Важное исправление: PRIMARY KEY библиотеки — `(client_id,id)`, а не глобальный
`id`. `LegacyProgramBookSourceReader.ts` теперь допускает одинаковый library ID
у разных клиентов. Same-client hint определяется точной парой; наличие такой
пары у другого клиента не делает собственную пару конфликтной. Дубликат той же
пары отклоняется. Книги, назначения и факты клиентов не сливаются.

## Реализованный source graph

`LegacyProgramStructureSourceReader.ts` читает физические строки
`training_programs → training_weeks → training_workouts → training_exercises`
в одном read snapshot с остальным R04. Для каждой строки сохраняются:

- account scope, таблица, исходный ID и ключ provenance;
- все исходные колонки, включая имя, заметки, JSON, порядок и deletion marker;
- исходная программа, клиент, ссылка на родительский source key;
- состояние формы JSON/lifecycle и фиксированные причины проверки;
- `targetId=null`: ни одна строка не становится автоматически программой 3.x.

Строки с признаком удаления не исключаются. Некорректный JSON не заменяется
пустым объектом, а отсутствие колонок не выдаётся за известные пустые значения.
Валидный object JSON означает только форму контейнера: вложенные факты и
настройки ещё требуют своей проверки.

Проверяются существование клиента/родителя, согласованность program ID у недели
и тренировки, изоляция владельца тренировки, допустимость и неоднозначность
порядка. Все строки с повторным порядком остаются в graph. Исправление порядка,
перепривязка к другой программе или угадывание связи по имени не выполняются.
Проблема родителя передаётся потомкам как причина проверки.

Тренировка без program/week ID сохраняет null и причины `UNASSIGNED_*`.
Это сигнал для дальнейшего разбора свободного режима, а не доказательство
повреждения или основание удалить тренировку. Маркер удаления также не является
доказательством удаления выполненных фактов.

Единый `r04:full` возвращает только агрегат `programStructure`: физические
счётчики, число строк с причинами проверки, отсутствие формы, deletion markers
и фиксированные коды. Названия, заметки, ID и JSON в отчёт не попадают.

## Проверки и оставшаяся работа

Синтетические проверки покрывают составной ключ библиотеки, исходную иерархию,
признаки удаления, конфликт program/week и владельцев, отсутствующих родителей,
некорректный JSON, неоднозначный/отрицательный порядок, неизвестную форму,
дубликаты ID и безопасный агрегат. Файловый тест полного R04 сверяет все четыре
счётчика и хеш источника до/после чтения.

Открыты: целевое объединение мезоциклов без слияния фактов, JSON программ и
архивов, плановые/фактические подходы и сегменты, ID ledger и target parity,
полный backup/restore, прерывание/нехватка места и Android. Новый граф не доказывает
завершённый перенос архивов или выполненных подходов. R04 остаётся PARTIAL,
D03/D04/R05/R06 и release gates OPEN. Реальный backup и телефон не открывались.
