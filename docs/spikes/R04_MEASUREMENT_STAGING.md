# R04: запись обхватов тела в staging

2026-10-24, база `60134d7`. R04 → R03; Product §§49.14–49.18, 49–50,
53–56, INT-03–12. Входы: immutable source/client IDs и уже реализованная
[точная проекция восьми обхватов](R04_MEASUREMENT_PROJECTION.md). Migration,
production DDL, overlay, signing и release gates OPEN. Только synthetic staging.

`readLegacyMeasurementsSnapshotInSnapshot` сохраняет все физические строки
`client_measurements`, все столбцы и пустые значения. Отсутствующая optional
таблица отличается от существующей пустой. При наличии проверяется полная
известная форма. Staging заново разбирает исходные значения; готовые flags
предварительного аудита не считаются доказательством корректности.

`stageClientMeasurements` подключает этот источник в общую транзакцию после
клиентов, анкет, рабочих данных, каталога, планов, шаблонов, архивов и фактов
тренировок. Режим требует всех этих владельцев; пропустить последнюю стадию
через более раннюю точку входа нельзя. Замороженная копия источника создаётся
до allocator и callback предыдущих владельцев.

## Что записывается

Существующая D01 baseline замеров применяется только к отдельному private R04
файлу: `body_measurements`, `measurement_daily_primary` и их индексы. Новых
production миграций нет. Добавлены только private ID map/receipt, mode binding
`MEASUREMENTS_REHEARSAL_V1` с явно заданным `referenceDay`.

- Один source atom `accountScope + physical row ID + field` получает один
  устойчивый UUID. Одинаковые числа/даты/названия не объединяют наблюдения.
  Клиент определяется проверенной ID map; неизвестный owner блокирует общую
  транзакцию. При replay сохраняются ID, проверяются источник и все target rows.
- Восемь обхватов в сантиметрах переводятся точно в десятые. Рука/бедро/икра
  остаются без стороны. Ни вес, ни процент жира этим источником не создаются.
  Время измерения неизвестно: localMinute=null; created/updated target записи
  равны времени импорта с явным `IMPORT_TIME`, не времени факта измерения.
- Явный referenceDay закреплён в binding/receipt. Повтор на следующий день или
  смена часового пояса компьютера не выбирает новый день проверки автоматически.
  Для существующего валидатора календарная дата создаётся на локальный полдень;
  дата замера остаётся исходной, искусственного времени у факта не появляется.
- Неподдерживаемая точность/диапазон, нуль, неверные значения/даты и будущая дата
  остаются в полном source receipt и списке provenance с причинами review и
  targetId=null. Для них нет нулевых, округлённых или обрезанных измерений.
  Число таких значений возвращается явно: они не объявляются перенесёнными
  нормальными фактами. Политика их дальнейшего представления ещё не завершена.
- Основные значения дня не назначаются. Несколько измерений остаются в журнале;
  обычное правило приложения показывает неоднозначность до явного выбора.
- Receipt сохраняет исходные пустые строки/добавочные поля, source SHA, ID map,
  target rows и соответствие каждого непустого поля. Контрольная сумма target
  manifest защищает также provenance от незамеченных изменений. Guarded read
  проверяет предыдущих владельцев и все таблицы этой стадии.

## Проверка

440/440 целевых тестов: `r04:plans:test` вместе с measurement projection,
source preflight, measurements extended и Navy. Добавлены10 тестов стадии и один
тест общей транзакции с непустыми планами/выполненными подходами/рабочими данными.

Проверены все восемь типов, несколько одинаковых наблюдений за день, разные
клиенты, пустые строки, исходные extras/timestamps, точность/диапазон/даты/review,
неизвестный owner, дубли физического ID, замороженный input, изменение значений/
владельца/ID/provenance/source, несовместимый mode/referenceDay. Новые3 checkpoints
и before-commit дают полный rollback всех владельцев/Client IDs и чистый retry.
Файловый read-only источник не изменился; reopening/reordering/retry сохраняют
target bytes и все ID без повторного allocator.

Синтетические D01 строки скопированы в свежую обычную БД через настоящий runtime
catalog. `DevMeasurementRepository` читает их без importer tables, показывает
несколько замеров дня, принимает явный primary, исправляет тот же ID/revision и
сохраняет выбранный primary. Это проверка совместимости данных с репозиторием,
не подключённый экран legacy restore и не доказательство Android сценария.

Root/mobile TypeScript, ESLint изменённых файлов, source73, sensitive-files и
diff check прошли. Новых bundle/APK/native/телефон/fullfoundation запусков нет.
Тест зарегистрирован в R04/Plans/foundation; параллельные theme changes исключены.
