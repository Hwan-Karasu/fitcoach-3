# R04: точные числа JSON без зависимости от Node reviver context

2026-10-24. Входы: существующие преобразователи Execution metrics, Nutrition,
Nutrition archive days и Calendar planner JSON. Зависимости R03/R04; Product
§§48.5.7,49–50,53–56 / INT-03–12. Production DDL, migration, Android overlay,
signing и release gates OPEN. Этот срез не открывает пользовательскую БД,
не меняет схему, не подключает полный импорт к приложению.

## Найденная несовместимость

Host-проекции брали точное написание JSON-числа из `reviver context.source`.
Округлённый JavaScript Number использовать нельзя: `7.00000000000000001` может
стать `7`, `9007199254740993` — другим целым; теряются также исходная дробная
точность, экспонента и знак `-0`.

Установлены React Native 0.86.3 и hermes-compiler 250829098.0.17. Локальный
`react-native/sdks/.hermesv1version` указывает `hermes-v250829098.0.17`.
В исходнике этой версии `RuntimeJSONParser::operationWalk` вызывает
`Callable::executeCall2`, передавая только key/value:
[RuntimeJSONUtils.cpp, строки 570–577](https://github.com/facebook/hermes/blob/hermes-v250829098.0.17/lib/VM/JSLib/RuntimeJSONUtils.cpp#L570).
Полученный Git blob SHA: `64d4d5ae5b87edb60728a48df2a20859cd19fcf7`.
Это проверка закреплённого исходника, не наблюдение работающего Android runtime.

## Реализация

Мобильный pure TypeScript `features/legacy-import/domain/SourceJson.ts`:

- первый стандартный `JSON.parse` проверяет исходную грамматику и выявляет
  строки, с которыми нельзя спутать временные числовые теги;
- небольшой проход по исходному тексту пропускает строковые литералы и заменяет
  только числовые токены на временные строки с точным исходным написанием;
- второй стандартный `JSON.parse` создаёт объекты, после чего итеративный проход
  передаёт числовые токены преобразователю; округлённые числа первого прохода
  никогда не используются для значений фактов;
- первый разбор обязателен: без него невалидный числовой ключ `{1:2}` после
  экранирования мог бы стать допустимым строковым ключом;
- теги не сохраняются и не возвращаются как исходные строки. Строки, в том числе
  экранированные управляющие символы, не преобразуются в числа. Сохраняются
  native duplicate-key/порядок ключей/безопасное создание `__proto__`;
- ошибки синтаксиса имеют фиксированный текст, исключения самого преобразователя
  не скрываются. Нет Node API, патча глобального JSON, новых зависимостей,
  рекурсивного обхода или дополнительного искусственного ограничения глубины.

Цена — два штатных разбора и временные данные, линейные от размера JSON. Это
осознанный обмен дополнительной работы при импорте на сохранение точности и
использование штатной проверки синтаксиса. Пределы памяти/скорости на Android
для больших пользовательских источников ещё не измерены.

Все четыре существующие проекции используют эту функцию. Публичные данные,
semantics, source/manifest hashes и версии staging не менялись: заменён механизм
получения тех же числовых токенов. Новая граница `legacy-import` не подключена к
обычным читателям 3.x и может удаляться с переходным импортёром.
