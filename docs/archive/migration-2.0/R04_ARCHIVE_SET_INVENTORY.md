## Почему нельзя просто импортировать каждый элемент

Архив книги 2.0 сохраняет объединённые `weeks/workouts` и исходные снимки
мезоциклов в `cycles[].snapshot`. Один и тот же подход может присутствовать
сразу в двух представлениях, а также в `training_session_sets`.
Кроме того, наличие строки, completedAt или одинаковых метрик само по себе
не является доказательством отдельного выполненного факта.

Builder записывает `sourceFactId` из `set.data.historyOriginId` либо ID исходного
set log. Старый архив может не содержать workouts, sourceFactId или подробностей
упражнений. Их нельзя заменить выдуманными пустыми значениями или новыми фактами.

## Реализованный учёт

`LegacyArchiveSetInventory.ts` читает все `training_archive_entries` в одном
read snapshot с R04, включая строки с deletion marker. Сохраняет полный исходный
ряд и JSON; вложенные массивы обходятся итеративно, без рекурсивного вызова JS.

Для каждого физического элемента `sets[]` сохраняются account, клиент, archive ID,
путь в исходном JSON, root/cycle representation, исходное значение элемента,
source fact ID или причина невозможности его определить, а также кандидаты метрик.
Путь — происхождение вхождения, он не используется как ID выполненного подхода.
Невалидный элемент не исчезает из учёта.

Явный sourceFactId и `data.historyOriginId`, если есть оба, должны согласоваться.
Конфликт и недопустимый тип помечаются, произвольный первый ID не выбирается.
Отсутствующая логическая identity остаётся null. Сохраняются исходные rpe,
setKind, effortOutcome, completedAt, data и segments; сегмент не становится
отдельным выполненным подходом.

Метрики проходят общий `convertLegacySetMetrics` с session rows: точный перевод
кг → целые граммы, пустота отдельно от нуля, без округления/выдуманных повторений.
Неизвестные/числовые JSON-типы текстовых полей не нормализуются молча.

Сводка отмечает:

- число root/cycle вхождений, неполных identity и метрик;
- повтор sourceFactId в пределах account/client;
- пересечение root и cycle для одного ID в том же архиве;
- несовпадение корректно разобранных метрик у повторов;
- ссылки по ID на session rows того же account/client и расхождения метрик.

Это сигналы для последующего разбора: ни совпадение ID, ни совпадение метрик
не запускает слияние. Пересечение представлений не объявляется доказанным
тождеством при конфликте значений. Другой клиент/account не подставляется.
targetFactId=null, targetFactsCreated=0, targetWrites=0.

Некорректная форма фиксируется по пути. Отсутствующий у старого снимка массив
отличается от явно пустого массива. Непрочитанная ветка остаётся в исходном JSON,
её содержимое не объявляется проверенным.

## Интеграция, проверки, границы

Единый `r04:full` содержит агрегат `archiveSets`. Публичный отчёт не выводит
source IDs, имена, заметки, пути, JSON или результаты подходов.
Проверки синтетические: root/cycle overlap, конфликты, owner/scope isolation,
утрата identity, старый формат, повреждение вложенных структур, raw сегменты,
метрики, удаление, дубликат физического ID и неподдерживаемая схема.
Файловая интеграция полного R04 проверяет root/cycle/session сигналы и
неизменность байтов источника. Реальная пользовательская база не открывалась.

Открыты: подтверждённый canonical fact ledger между архивом, set logs,
session sets и exercise history; семантика сегментов/типов подходов; разрешение
конфликтов и отсутствующих ID; target parity; запись в staging и безопасный
cutover; backup/restore, interrupted/low-disk и Android. Текущий проход не
пересчитывает статистику и не подтверждает полноту переноса истории.
