# Питание — сверка реализации и приёмки, 21.10.2026

Статус: **DEV IMPLEMENTATION / ANDROID ACCEPTANCE IN PROGRESS**, не production DONE. Эта адресная сверка уточняет исторические NUTRITION_PARITY_MATRIX/NUTRITION_V11_MATRIX; старые записи не являются доказательством нового diff.

Источники: Product §49 и §§53–56 из синхронизированного пакета; UX v1.1 P-01…48 и NUT-FS-01…44; референс 15 экранов от 20.10.2026; ADR-025/026/027 и прямые ответы владельца в текущем диалоге. Основной этап N01, связанные изменения N02/N04 через существующие порты, без смены архитектуры.

## Нормативные расхождения и согласования

- Product §49.5 п.1–2 против per-entry override: прежнее решение владельца ADR-026. Исходный снимок остаётся неизменным; nullable override принадлежит записи, масштабируется с количеством, CAS; возврат к значениям добавления. Production поправка/DDL остаются за source-gate/D01.
- §49.2/49.10 и UX v1.1 о целях уточнены ADR-025/027: не восстанавливать экран целей по дням/генератор предложений. Расчёт/ручная корректировка сохраняют поздние решения владельца и исторический resolver.
- §49.14 уточнён ADR-026: Л/П и legacy без стороны; эта сессия не переписывает владельца замеров.
- В §49.1/49.3–49.4 нет отдельного SavedMeal. Владелец выбрал **наборы отдельно для каждого клиента**. Proposal для Product/Feature/Data: клиентский набор хранит имя и массив снимков/порций, не является рецептом или меню; добавление разворачивается в отдельные дневные записи одной транзакцией; правка набора не меняет историю. Реализовано только в dev v11.
- Референс FatSecret требует больше полей рецепта. На предложение optional details владелец ответил «делаем как в fat secret»; в ответ явно сохранены правила главного UX-контракта: фото/описание/шаги необязательны, один ингредиент достаточен. Dev v12: минуты подготовки/приготовления, категории, инструкции, локальная фотография. Обязательные 3 ингредиента/3 шага/фото без новой продуктовой поправки не навязаны.
- Dev v13 отделяет клиентские поисковые запросы от употребления. Dev v14 сохраняет idempotency receipts batch-команд. Эти таблицы не production DDL. Облачные/платные сервисы и внешние пищевые базы не подключены.
