## 1. Резюме решения (APPROVED: гибрид C)
Один раздел «История занятий» с двумя режимами: **«Тренировки»** и **«Упражнения»**.
- «Тренировки»: список программ → выбранная программа → (для PERIODIZED) горизонтальная лента мезоциклов → вертикальный список раскрываемых карточек тренировок → строки выполнений по неделям → «Детали выполнения» → «Открыть в дневнике».
- «Упражнения»: поиск упражнения клиента → существующий экран «Упражнение клиента» («Обзор | История | Прогресс») с общим фильтром области и периода.
- «История занятий» отвечает на вопрос «что и когда выполнялось»; «Статистика» — «какие показатели». «Архив программ» остаётся на экране «Тренировки» (вкладки «Программы | Шаблоны | Архив программ») и с историей выполнений не смешивается.

Критерии качества: понятный контекст (программа/мезоцикл/тренировка/режим); без лишних экранов на каждый уровень; возврат сохраняет контекст; историческая достоверность; без remount при смене чипа и раскрытии карточки.

## 2. Информационная архитектура и маршруты
```
Карточка клиента → Ещё
├─ История занятий
│   ├─ [Тренировки]
│   │   ├─ Список программ с историей
│   │   └─ Программа (PERIODIZED: лента мезоциклов | SIMPLE: без ленты) → карточки тренировок → выполнения
│   │         └─ Детали выполнения (read-only) → «Открыть в дневнике» (если есть слот плана) → Упражнение → История/Прогресс
│   └─ [Упражнения] → Упражнение клиента: Обзор | История | Прогресс
└─ Статистика (существующий отдельный раздел)
Тренировки → Программы | Шаблоны | Архив программ  (не переносить)
```

### 2.1 Навигационные правила
- Стартовый режим — последний использованный, пока открыта карточка клиента; первый вход — «Тренировки». Чужие клиенты не подставляются.
- Выбор программы открывает её контекст; «назад» возвращает список на прежнюю позицию. **Название программы — подзаголовок шапки (APPROVED)**, второй «‹» в теле экрана нет.
- Выбор мезоцикла не добавляет страницу в стек: меняется активный чип и содержимое.
- Открытие выполнения — отдельный маршрут «Детали выполнения»; возврат в тот же контекст.
- Из деталей/выполнения упражнение открывает историю с контекстом (программа/мезоцикл/тренировка), снять ограничения — одним касанием до «За всё время».
- Вход из «Упражнения» не навязывает контекст программы.
- История **не создаёт и не меняет** `dev_training_sessions` и **не вызывает** `selectProgram/selectMesocycle` (в отличие от `ProgramScreen`; его не переиспользовать).

## 3. Режим «Тренировки»
### 3.1 Список программ
- Сверху: переключатель `Тренировки | Упражнения`; поиск по названию программы; фильтры периода и статуса.
- Карточка: название, пометки «Архивная»/«Исходный план удалён», «Проведено · Записей · Рабочих подходов», для PERIODIZED — число мезоциклов с историей. **Тоннаж в кратких карточках не показывать (UX-C11).**
- В списке — программы с записями (`IN_PROGRESS/COMPLETED/MISSED/CANCELLED`); пустые планы — в «Программах». Архивные участия и программы с удалённым планом остаются.
- Сортировка — дата последнего занятия ↓; при равенстве — стабильно по идентичности (PC §50.4.1). Пусто: «История занятий пока пуста».

### 3.2 Программа
- Контекст: короткая строка «Проведено · Записей · Рабочих подходов».
- **Лента мезоциклов (PERIODIZED):** чипы с названиями, выбранный — фон/рамка + текст; при ≥ 10–15 мезоциклов — «Все мезоциклы» с поиском; порядок — установленный порядок мезоциклов. SIMPLE — ленты нет.
- **Программа с удалённым планом (APPROVED):** ленты нет; один блок «план удалён»; тренировки группируются по `plannedWorkoutId`; мезоцикл — подпись из снимка у каждого выполнения; без миграции снимка.
- **Список тренировок:** виртуализированная лента раскрываемых карточек; группировка по идентичности: PERIODIZED — `lineageId` тренировки в пределах `(clientId, programId, мезоцикл)`; SIMPLE — `plannedWorkoutId` (правка «только этой недели» хранится по ключу неделя+`workout_id`, id сохраняется). Заголовок группы — актуальное название; **если названия по неделям различаются, заголовок — название ближайшего по дате выполнения (если его нет — ближайшее непустое, иначе «Тренировка»); реализовано в P1 (`workoutGroups`)**.
- **Раскрытие:** строки выполнений по неделям, новые сверху: «Неделя N · дата», явный статус, рабочие подходы, при наличии — время и длительность. Подходы всех выполнений в аккордеоне не показывать.
- Состояние раскрытия — по ключу `(clientId, programId, мезоцикл, группа тренировки)`; скролл хранится отдельно для каждого мезоцикла.

### 3.3 Детали выполнения (новый read-only экран, APPROVED)
- Верх: дата, статус, контекст «Программа / Мезоцикл / Неделя / Тренировка», пометки (архив, план удалён), время начала и длительность (если есть).
- Тело: упражнения и подходы — тип (разминка/рабочий/отказ/дроп), значения, стороны, RPE, заметки, признак «не засчитан»; не засчитанные подходы визуально и текстом отделены.
- Действия: «История упражнения» у каждого упражнения; «Открыть в дневнике» — только если есть слот плана; без слота (план удалён) — только просмотр.
- Открытие деталей **не создаёт сессию** и не меняет выбранный план (PC §50.4.4).

### 3.4 Статусы и счётчики
| Статус | В истории | «Проведено» | Время/длительность |
|---|---|---|---|
| COMPLETED | да | да | по валидной паре отметок |
| IN_PROGRESS с фактами | да, «В работе» | нет | по валидной паре; одно автоначало — без длительности |
| MISSED | да | нет | по валидной паре (PC §48.86.17) |
| CANCELLED | да | нет | по валидной паре (PC §48.86.17) |
| NOT_STARTED без событий | нет | нет | — |
| план удалён, факты сохранены | да (read-only) | по сохранённому исходу | по сохранённым отметкам |

«Записей» — все включённые сессии; «Проведено» — только COMPLETED (§48.51); **«Рабочих подходов» — единая функция `isWorkingSet` (засчитанные, без разминки), APPROVED**.

## 4. Режим «Упражнения» и прогресс
### 4.1 Список
- Упражнения с фактами **этого клиента**, включая архивные свои (**с пометкой «(архив)», APPROVED**); поиск по текущему имени/псевдонимам без объединения одинаковых названий; сортировка — последняя дата ↓ (или по алфавиту). Строка: название, последняя дата, число занятий. Переход — в существующий `ClientExerciseScreen`.
- Для исторических чтений каталог должен разрешать архивные определения (имя и профиль не пропадают из истории/графиков).

### 4.2 Экран упражнения
- Вкладки «Обзор | История | Прогресс».
- **Фильтры (APPROVED): три пилюли — программа, мезоцикл, тренировка** (общие для «История» и «Прогресс», единый паттерн с историей, статистикой и месячным отчётом; `HistoryFilter` расширяется третьим уровнем). Показывать итоговый контекст и «Сбросить»; выбор другого родителя сбрасывает лишь несовместимые дочерние значения.
- **Период (принято как новое решение сверх PC §37.4):** 30 дней / 3 мес / 6 мес / год / всё время / свой — общий для «Истории» и «Прогресса».
- **История:** занятия по датам с временем начала и длительностью при наличии, раскрываемые результаты, переход к выполнению; два вхождения упражнения в одну тренировку различаются в деталях.
- **Прогресс:** метрики по профилю учёта, график, рекорды, e1RM (оценка по Бжицки, 1–12 повторений, не измеренный максимум). Подтверждённые рабочие подходы занятий со статусом IN_PROGRESS, MISSED и CANCELLED **входят в графики с текстовой меткой статуса и отличимой точкой (APPROVED)**; нет данных — «Нет данных», не 0.
- Дополнительный режим «повторения при фиксированном весе» — следующий этап.

### 4.3 Точки входа
| Откуда | Куда | Область по умолчанию |
|---|---|---|
| История → Упражнения → упражнение | Упражнение / История | Всё время |
| Выполнение → упражнение | Упражнение / История | Контекст исходной тренировки |
| Дневник → название упражнения | Упражнение / История | Текущий контекст плана, «Всё время» доступно |
| Статистика → показатель упражнения | Упражнение / Прогресс | Осознанно переданные фильтры |

## 5. Состояние, сохранение контекста и мерцание
- **Правило сохранения (принято):** режим, программа, мезоцикл, фильтры, раскрытия и позиции скролла живут, пока открыта карточка клиента; фильтры статистики приводятся к тому же правилу (сегодня — модульная `Map` на время работы приложения).
- Инварианты: A→B→A возвращает прежний список/раскрытие/скролл; программа A→B→A не показывает цикл чужой программы; родительский экран и шапка не размонтируются при смене мезоцикла; устаревшие ответы не замещают новый контекст; фиксированный каркас контролов во время загрузки; адресное обновление без полного перечитывания несколькими экранами.
- Скролл-позиции: отдельно для списка программ, `(clientId, programId, мезоцикл)` и списка упражнений; восстановление после появления данных, offset ограничивается доступной высотой.
- Состав состояния — концепция, без нового глобального Context.

## 6. Время занятия (PC §48.86.10/13/17 — APPROVED; детали UI — PROPOSED)
- Данные: nullable `started_at`/`finished_at` у **сессии** (не у программы/плана), хранение абсолютного момента; `duration` вычисляется в одном доменном месте при валидной паре; старые записи — `NULL`, значения не выдумываются.
- **Авто-начало** — при первом подтверждённом подходе (предварительное значение); **авто-окончание** — при «Завершить»; обе отметки правятся вручную (в том числе задним числом). Время ввода подходов само по себе не длительность.
- Отмена завершения/смена исхода не стирает отметки; повторное завершение не переписывает вручную исправленное окончание. Повторный запуск приложения, импорт, копирование длительность не создают.
- Показ: «Начало HH:MM · Длительность X ч Y мин»; нет пары — «Нет данных»/«Длительность не указана»; окончание раньше начала — «Нет данных» до правки; переход через полночь работает, `actual_date` без команды не меняется.
- Таймеры отдыха не определяют длительность; календарь с дневником не связывается (PC §48.39).
- **Открыто (UI/Technical Design):** способ ручной правки отметок; часовой пояс отображения; поведение при правке `actual_date`; сортировка старых записей без времени.
- Технически: миграция dev-схемы дневника (новая версия журнала `training_execution_schema_migrations`), CAS/revision, тесты полуночи, правок и обратной совместимости; production DDL — только после гейтов.

## 7. Семантика и историческая идентичность
- Группировка — по идентификаторам, не по названию. Исключение (APPROVED): блок «план удалён» группирует по `plannedWorkoutId`, мезоцикл — подпись из снимка.
- Названия (UX-C13): действующий план — актуальное название; план удалён с сохранением истории — название из `origin_json`, при его отсутствии — честная заглушка. Переименование не меняет `session.id`, `exercise_id` и факты.
- Факты сохраняются: `session.id` и `exercise_id` — основа открытия результата; архивация упражнения не удаляет его имя/профиль из аналитики; смена профиля учёта своего упражнения после появления фактов требует отдельной проверки (сегодня не проверяется); полное удаление с результатами — утверждённая осознанная команда (PC §48.11/§48.30/§50.3).
- Подходы и объём: единая функция рабочих подходов; «Объём» без определения из новых карточек убирается; тоннаж остаётся в статистике/прогрессе по `factTonnage` (с массой тела, `null` при невычислимости).

## 8. Визуальная спецификация
- Действующая дизайн-система FitCoach 3.0: шрифт `fonts.*`, иконки `lucide-react-native`, цвета только из токенов, hit-area ≥ 48dp; одна строка шапки.
- Сверху — переключатель режимов; в программе — лента мезоциклов и список тренировок без тяжёлой постоянной сводки. Иерархия: название тренировки → дата и неделя → счётчики.
- Цвет типа недели — только метка недели (с текстом); статусы различаются не только цветом; длинные названия не ломают вёрстку (чипы адаптивной ширины, полный список по «Все мезоциклы»).
- Все схемы в v1.1 — иллюстративные; макеты экранов делаются отдельно.

## 9. Состояния и крайние случаи
Пустая история; одна программа; SIMPLE без мезоциклов; 15–30 мезоциклов; цикл без выполнений («пока нет истории»); одинаковые названия (группировка по id); несколько занятий в день (по реальному времени, где оно есть); удалённый/заменённый плановый день (по достоверным ключам); план удалён (read-only, блок «план удалён»); архивированное упражнение (находится по id); выход клиента из общей программы (изоляция по `clientId`); загрузка после смены фильтра (без смешивания); нет вычислимого тоннажа («Нет данных»); нет времени («Время не указано»); занятие начато без окончания (длительность не выдаётся); через полночь; быстрый A→B→A; возврат из деталей.

## 10. Техническая организация (без преждевременного рефакторинга)
- Переиспользовать: `createTrainingHistory`/`TrainingHistoryEntry`, `exerciseSessions`, `exerciseActivity`, `progressSeries`, `repRecords`, `LineChart`, `BarChart`, `SegmentedControl`, `FilterPill`, `HistoryFilterBar` (расширить), `StatusTag`, `PeriodPill`, `EmptyState`, маршруты открытия тренировки/упражнения.
- Нужно: поле `lineageId` тренировки в записи истории; заметки и RPE в записи; read-only «Детали»; историческое чтение каталога с архивными определениями; единая функция рабочих подходов; фильтр «Тренировка» в `HistoryFilter` и `sanitizeFilter`.
- Производительность: сначала замер на ~500 занятиях/~10 тыс. подходов (`history.list`, повторные чтения при коммитах дневника, commits, возврат из деталей), затем адресные запросы/кэш; без второго конкурирующего хранилища истории.
- Тесты: группировка и фильтры, `planDeleted`, SIMPLE/PERIODIZED, `lineageId`, архивное упражнение, статусы и счётчики, время (полночь, валидная пара, отмена); UI — возврат, быстрое переключение, скролл; проверка на устройстве.

## 11. План (после утверждения дизайна)
P0 — внести решения в контракт/PC (в т.ч. PC §50.1 про расположение «Архива программ»). P1 — модель представления (селекторы, `lineageId`, архивные упражнения, единая функция подходов, правило заголовка группы). P2 — гибридный интерфейс «Тренировки». P3 — режим «Упражнения», фильтры из трёх пилюль, общий период. P4 — навигация и непрерывность (деталь → дневник → возврат). P4b — время занятия (миграция, авто-отметки, ручная правка). P5 — измерения и полировка.

## 12. Приёмка (AC)
AC-01 два режима без дублирования шапки · AC-02 PERIODIZED: лента реальных мезоциклов · AC-03 SIMPLE: без ленты · AC-04 A→B→A сохраняет раскрытие и скролл · AC-05 раскрытие тренировки показывает выполнения по неделям · AC-06 открытие деталей не создаёт сессию · AC-07 план удалён: блок «план удалён», read-only · AC-08 упражнение из выполнения открывает историю в контексте · AC-09 сброс области показывает все факты клиента · AC-10 каскад программа→мезоцикл→тренировка без смешения lineage · AC-11 архивное упражнение остаётся в истории и графиках · AC-12 изоляция клиентов общей программы · AC-13 правка результата и возврат: данные свежие, контекст сохранён · AC-14 быстрая смена циклов без устаревших данных и remount шапки · AC-15 «Проведено» только COMPLETED · AC-16 нет данных ≠ 0 · AC-17 ~500 занятий: замеры до/после · AC-18 возврат из деталей сохраняет фильтры, цикл, раскрытие, скролл · AC-19 краткая карточка без тоннажа · AC-20 IN_PROGRESS/MISSED/CANCELLED с подходами — в графиках с меткой · AC-21 переименование не меняет факты · AC-22 удаление плана с историей: сохранённые названия · AC-23 старая запись без времени — без выдуманных значений · AC-24 авто-начало по первому подтверждённому подходу, авто-окончание при «Завершить», ручная правка → длительность · AC-25 IN_PROGRESS без окончания — длительность не выдаётся · AC-26 через полночь — корректно, `actual_date` не меняется · AC-27 (v1.2: заменён) отмена завершения и повторное «Завершить» не стирают и не переписывают вручную исправленные отметки · AC-28 миграция сохраняет существующие сессии и факты (nullable-поля).

## 13. Риски
Неверная группировка при совпадении названий (id + тесты); потеря истории после удаления плана (read-only + `origin_json`); смешение клиентов общей программы (`clientId`); две формулы объёма (единая функция); архивные упражнения (историческое чтение каталога); дублирующие подписки перечитывают историю (замер, адресные обновления); мерцание/скролл (стабильная идентичность экрана, runtime-проверка); дублирующие `ClientWorkspace` при открытии тренировки (проверка back-stack на устройстве); тесный экран (компактные карточки, тест длинных названий).

## 14. Реестр решений
**APPROVED владельцем:** UX-C01 гибрид C; UX-C11 краткие показатели без тоннажа; UX-C12 незавершённые занятия с подходами в графиках с меткой (расширено на MISSED/CANCELLED); UX-C13 актуальное название, снимок при удалённом плане; UX-C14 время и длительность в текущей фазе (механика — PC §48.86.10/13/17); **v1.2:** название программы в подзаголовке шапки; пилюли + «Тренировка»; блок «план удалён»; read-only «Детали»; архивные упражнения с аналитикой; единая функция рабочих подходов; AC-27 backup убран; общий период; правило сохранения «пока открыта карточка клиента».
**PROPOSED без обсуждения (UX-C02–C10 из v1.1):** два режима внутри истории; SIMPLE пропускает мезоциклы; группировка по ID; выполнения в раскрытии, подходы — в деталях; нет сессии при просмотре; программы с историей по умолчанию; история упражнения доступна напрямую; сохранение контекста; без крупного рефакторинга до замеров.
**Открыто:** правка отметок времени вручную; часовой пояс; поведение при смене `actual_date`; сортировка старых записей без времени.
