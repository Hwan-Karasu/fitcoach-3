# История занятий — решения владельца к UX-контракту v1.1 (2026-10-20)

Основа: «FitCoach 3.0 — UX-контракт истории v1.1» (внешний документ), аудит `docs/HISTORY_STATS_AUDIT.md`, коммит кода `1262e56`.
Ниже — ответы владельца на вынесенные расхождения. Контракт v1.2 должен их отразить; код не менялся.

| № | Вопрос | Решение |
|---|---|---|
| 1–3 | Время занятия | Строго по PC §48.86.10/13/17: авто-начало по первому подтверждённому подходу, авто-окончание при «Завершить», ручная правка обеих отметок; длительность при любом исходе с валидной парой; отмена/повторное завершение не стирают и не переписывают отметки. Кнопку «Начать занятие» не вводить. Открытым остаётся только способ ручной правки (UI/Technical Design). |
| 5 | Шапка внутри истории | Название программы — подзаголовок шапки (`ClientHeader`); без второй «‹ История / …» в теле экрана. |
| 6 | Фильтр области | Оставить пилюли «программа / мезоцикл» и добавить третью «Тренировка»; единый паттерн для истории, статистики, месячного отчёта и упражнения (`HistoryFilter` расширяется). |
| 7 | План удалён с сохранением истории | Один блок «план удалён»: тренировки группируются по `plannedWorkoutId`, мезоцикл — подпись из снимка у каждого выполнения; ленты мезоциклов нет; без миграции снимка. |
| 10 | «Детали выполнения» | Новый read-only экран для всех записей: История → Детали → «Открыть в дневнике» (для записей без слота плана — только просмотр). |
| 11 | Архивные свои упражнения | Показывать с полной аналитикой: историческое чтение каталога разрешает архивные определения; в списке «Упражнения» помечены «(архив)». |
| 12 | «Пропущена»/«Отменена» с подтверждёнными подходами | Учитывать в графиках с текстовой меткой статуса (как для «В работе»). |
| 13 | «Рабочих подходов» | Единая функция (засчитанные, без разминки — `isWorkingSet`); старые «Подходов/Объём» в карточке истории заменяются; «Объём» без определения из новых карточек убирается. |

## Не решено (по умолчанию — рекомендация)
- **AC-27 «восстановление backup»**: в 3.0 нет резервного копирования — убрать из AC (рекомендация).
- **Общий период для «Истории» и «Прогресса»** (сверх PC §37.4) — принять как новое решение (рекомендация).
- **Правило сохранения фильтров**: «пока открыта карточка клиента» или «пока открыто приложение» — выбрать одно (рекомендация: пока открыта карточка клиента; фильтры статистики привести к тому же).

## Уже выяснено
- Простая программа: правка «только этой недели» хранится по ключу (неделя, `workout_id`), id тренировки сохраняется ⇒ группировка по `plannedWorkoutId` работает; заголовок группы в разных неделях может различаться — правило заголовка нужно задать.
- История не должна вызывать `selectProgram/selectMesocycle` (в отличие от `ProgramScreen`).
