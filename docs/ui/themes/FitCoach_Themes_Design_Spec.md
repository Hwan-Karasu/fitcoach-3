# FitCoach — спецификация 6 тем и 18 акцентных сочетаний

**Версия:** 1.0 · **Формат:** дизайн-спецификация для Claude Code / Codex · **Статус:** предложение к реализации; требуется сверка с репозиторием.

## 1. Что именно должно работать

В приложении доступно **6 базовых тем**. В каждой теме пользователь выбирает **один из 3 акцентных цветов**, всего **18 сочетаний**. Цвета фона, поверхностей, текста, разделителей и навигации принадлежат теме. Выбор акцента меняет цвет основных активных и интерактивных элементов, но не перестраивает интерфейс и не меняет бизнес-логику.

**Важно:** значения HEX — осознанно подобранная спецификация по изображениям, **не точное считывание RGB из сгенерированного макета**. Изображения приблизительны и не могут заменить проверку цветовых ролей.

## 4. Структура семантических токенов

Точные значения и все производные состояния находятся в **`fitcoach_themes_v1.json`**. Там определены:

- `colors.background`, `surface`, `surfaceElevated`, `surfaceSecondary`, `navigation`;
- `colors.textPrimary`, `textSecondary`, `textMuted`, `iconPrimary`, `iconSecondary`;
- `colors.border`, `divider`, `success`, `warning`, `error`, `info`;
- `accents.{id}.base`, `onAccent`, `pressed`, `soft`, `onSoft`, `focusRing`;
- `defaultAccentId`, `appearance`, `weekPaletteSlots`.

При интеграции используй существующие названия токенов FitCoach, если такие уже есть: адаптируй JSON через слой сопоставления, **не создавай дублирующие конкурирующие системы тем**.

### Обязательные роли в компонентах

| Компонент | Фон | Текст/иконки | Выделение |
|---|---|---|---|
| Корень экрана | `background` | `textPrimary` | — |
| Карточки | `surface` | `textPrimary` / `textSecondary` | бордер `border` |
| Вторичные блоки | `surfaceSecondary` | `textPrimary` | — |

| Ошибка/успех/предупреждение | семантические токены | по контексту | не зависят от выбора акцента |

## 5. Приоритеты цветов и контекст тренировочной недели

1. **Базовая тема** определяет нейтральные поверхности, текст, разделители и статусные цвета.
2. **Выбранный пользовательский акцент** определяет глобальный primary-action, активную навигацию, чипы, фокус и обычные selected-состояния.
3. **Цвет типа тренировочной недели** задаётся существующей предметной логикой FitCoach; он не тождествен пользовательскому акценту. Он может окрашивать контекстные элементы недели/программы, но не должен заменять семантические `error/success/warning` и не обязан перекрашивать всю глобальную навигацию.
4. `weekPaletteSlots` в JSON — только **предлагаемые цветовые слоты**. Они **не являются** готовым mapping категорий. После просмотра контракта сопоставь их реальным категориям, сохрани существующие пользовательские назначения и идентификаторы.
5. Смена глобального акцента не меняет историю, типы недель и ранее сохранённые пользовательские значения.

## 6. Поведение переключателя

Экран `Настройки → Оформление`: каталог из 6 тем, внутри выбранной темы — три радиоварианта акцента. Предпросмотр происходит сразу, изменения сохраняются в существующем пользовательском хранилище настроек. После перезапуска выбираются последние корректные значения. Для legacy-настроек должен существовать безопасный mapping/fallback; отсутствие сохранённой темы не должно приводить к ошибке. Не меняй представление существующих данных тренировок.

## 7. Контрастность

Рассчитаны пары для основного/вторичного/приглушённого текста на поверхности, вторичного текста на фоне, текста на базовом/pressed/soft акценте. Проверка проведена формулой WCAG contrast ratio.

## 8. Неизменяемые UX-инварианты

- Экранный состав, навигация, сетка, иерархия данных, логика календаря, работа тренировок/питания/архива не меняются.
- Тема и акцент **не** должны размонтировать экраны, сбрасывать scroll offset, перезапускать таймеры, сбрасывать введённые результаты, делать лишние SQL-запросы или ломать Drag & Drop.
- Никаких глобальных поисков и замен HEX без проверки назначения, никаких массовых замен всех тёмных цветов акцентом.
- Контраст: обычный текст ≥ 4.5:1; крупный текст и значимые нетекстовые элементы ≥ 3:1 там, где применимо; при несоблюдении скорректировать токены, а не скрывать проблему.
- Визуальные сравнения делать на **одних и тех же данных**, чтобы видеть влияние исключительно темы и акцента.
