# F10 — локальная диагностика без пользовательских данных

**Статус 2026-10-15:** `PARTIAL / NOT DONE`. Основание: backlog F10,
Architecture §9. Зависимости F02/F04 остаются кандидатами; это не полный
production observability или security audit.

`LocalDiagnostics` хранит максимум 100 событий только в памяти (допустимый
предел 1–500). Событие строится заново из разрешённых полей: порядковый номер,
`db.transaction`, результат commit/rollback/reject, округлённая длительность
и фиксированный код ошибки. Произвольные `SQL`, bindings, ID, пути, исключения
и payload не сохраняются. Данные не отправляются и не пишутся в файл.

`WriterCoordinator` сообщает результат после завершения транзакции; ошибка
самого sink не меняет результат бизнес-записи. При quiescence отказ получает
отдельный код. Dev-only F04 SQLite-диагностика показывает только агрегатные
счётчики подтверждённых, откатанных и отклонённых транзакций на собственной
синтетической базе.

Четыре теста проверяют whitelist, вместимость, отсутствие утечки SQL/текста
исключения и независимость записи от сбоя диагностики. Открыто: typed codes
для реальных feature-команд, локальная политика хранения/очистки при
background, Android QA, security review и отсутствие внешней передачи на
уровне готовой сборки. `F10` не объявляется `DONE`.

После подключения прошли `diagnostics:test` 4/4, общий foundation suite 64/64,
`typecheck`, `lint`, `arch:check`, `source:verify`, `secrets:check` и Android
JavaScript bundle. Это не custom APK и не проверка на устройстве.
