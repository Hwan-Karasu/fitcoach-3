# Decisions (ADR)

Продуктовые и UI-решения владельца живут в нормативном пакете,
`docs/PROJECT_STATUS.md` и `docs/ui/UI_STYLE_DECISIONS.md`. Здесь —
технические решения и правила, которые нельзя нарушать.

## Неизменные правила

1. Источник истины — нормативный пакет (`AGENTS.md`); build120 — read-only.
2. V1 офлайн и только для тренера.
3. TypeScript strict; новые `.js`/`.mjs` не добавлять.
4. UI не обращается к SQLite; чужая фича — только через `public.ts`.
5. Запись в БД — только через `WriterCoordinator`; CAS по revision;
   `publish` после commit.
6. Календарь, тренировка и Credit Ledger — независимая семантика; правки не
   уничтожают факты.
7. Удаление клиента — только через участников-владельцев; без участника —
   fail-closed.
8. Статусы `OPEN/PROPOSED/PLANNED` не повышать без доказательства;
   production DDL, миграция, overlay APK, release — только после gates.
9. В Git нет секретов, JKS/PEM, паролей, реальных БД и PII
   (`npm run secrets:check`).

## Журнал

### ADR-001. Свой журнал миграций у каждого владельца данных (2026-10)
- Проблема: несколько фич пишут в один dev-файл SQLite.
- Решение: таблица `<owner>_schema_migrations` на владельца, общий файл через
  `SharedSqliteDatabase`.
- Альтернативы: общий журнал — связывает релизы фич; отдельные файлы БД —
  ломают атомарные кросс-модульные транзакции.

### ADR-002. Жесты календаря на RNGH + Reanimated (2026-10-16)
- Проблема: PanResponder пересоздавался при перерисовке, конфликт со скроллом.
- Решение: react-native-gesture-handler (Tap / Pan после долгого нажатия),
  геометрия — `"worklet"`-функции, колбэки через `scheduleOnRN`.
- Альтернативы: PanResponder + refs — хрупко и без нативного приоритета жестов.

### ADR-003. Тесты на Node strip-types без Jest (2026-10)
- Проблема: нужен быстрый запуск тестов домена и dev-хранилищ.
- Решение: `node --experimental-strip-types --test`, SQLite через
  `node:sqlite`-адаптер; тесты с `.tsx` — в `apps/mobile/scripts`.
- Альтернативы: Jest + babel — тяжелее и медленнее, лишняя конфигурация.

### ADR-004. Сначала проверенные библиотеки; перетаскивание — react-native-sortables (2026-10-17)
- Проблема: владелец требует не писать своё, если есть проверенная библиотека; конструктору анкеты
  нужно перетаскивание вопросов (§27.8) с автопрокруткой и переносом между разделами.
- Решение: перед новым модулем искать библиотеки (совместимость с Expo 57 / Reanimated 4, активность,
  лицензия) и предлагать владельцу; для перетаскивания — `react-native-sortables` (MIT, Reanimated 3/4,
  Expo, `Sortable.Grid` + `Sortable.Handle` + `scrollableRef`). Разделы и вопросы — один плоский список.
- Альтернативы: самописный жест на RNGH (написан и удалён), react-native-draggable-flatlist (давно не
  обновлялся), reanimated-dnd / drax (меньше пользователей). Готового конструктора анкет под RN нет
  (SurveyJS Creator и json-schema builders — только веб), доменные правила анкеты остаются нашими.

### ADR-005. Системный каталог упражнений — снимок RepDB Free через конвейер (2026-10-17)
- Проблема: нужен системный каталог (Product §29 утвердил RepDB Free), но RepDB не может быть доменной
  моделью, а лицензия запрещает публиковать набор как датасет.
- Решение: закреплённый коммит RepDB скачивается в `vendor/repdb/` (вне git), сборка нормализует в реестр
  FitCoach со своими ID `sys:repdb:<id>` и русскими названиями; сгенерированный JSON хранится в приватном
  репозитории как часть приложения. Если репозиторий станет публичным — убрать сгенерированный JSON и
  `repdb-names-ru.json` из истории и собирать их при сборке. Подпись RepDB — в каталоге и карточке.
- Альтернативы: free-exercise-db (Unlicense, но не утверждён продуктом), wger (CC-BY-SA, переводы
  неполные), только свои упражнения (тренеру долго заполнять).
