# Cross-feature read models

`QueryRegistry` хранит только временные снимки проекций. Ключ включает workspace,
client, канонические параметры и локальную дату. Зависимости задают домены и ID,
поэтому batch изменений обновляет только пересекающиеся запросы. Поздний ответ
старого запроса не заменяет актуальный снимок; при фоновом обновлении прежние
данные остаются на экране.

Владельцы модулей сохраняют бизнес-факты и выполняют записи. `writeWithChanges`
публикует manifest только после успешного завершения транзакции
`WriterCoordinator`. Этот слой не владеет схемой БД и не выполняет SQL.
Экраны подписываются через `useQuerySnapshot` на handle своего контроллера.

Production loaders и подписки экранов будут подключены после схем владельцев
и read-models (D01/D04/C01). Демонстрационные данные UI сюда не подключать и
не создавать ради этого вымышленные production-таблицы.
