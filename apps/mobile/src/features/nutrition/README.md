# Nutrition

Продукты, рецепты, снимки порций, дневник и действующие по датам цели.
Обновление каталога не изменяет историческое потребление.

Dev-only срез N01 ч.1 (`data/DevFoodCatalogRepository.ts`) живёт в общем dev-файле, журнал миграций
`nutrition_schema_migrations`. Таблица `dev_food_products` — общий каталог рабочего пространства (не привязан к клиенту).

- Собственный продукт (§49.3): название, марка, эталон `100 г` / `100 мл` / порция и значения ккал, Б, Ж, У
  в десятых долях. Незаполненный нутриент — `null`, а не ноль; продукт без единого значения отклоняется.
- `scaleNutrients` — пересчёт на фактическое количество (§49.3.3); нулевое или нечисловое количество — `INVALID_PORTION`.
- Удаление из каталога — скрытие (`archived_at`): `get(id)` по-прежнему читает скрытый продукт для истории (§49.5.2).
  Правка меняет только будущие использования; revision — защита от устаревшей правки.

N01 ч.2 (`data/DevRecipeCatalogRepository.ts`, миграция v2): рецепт из продуктов каталога (§49.4) — итог только сумма ингредиентов,
неизвестный нутриент ингредиента делает итог неизвестным. Дневник получает основы «1 порция» и «100 г» (последняя — только при указанной
массе готового блюда, без выдуманной массы). `FoodSnapshot` (`snapshotOfFood/Recipe`) — неизменяемый снимок для дневной записи
(§49.5.1): правка продукта и рецепта прошлые дни не меняет, состав рецепта в сумму дня повторно не входит. Состав заменяется целиком;
скрытый продукт нельзя добавить в рецепт заново, но он остаётся в рецептах, где уже был (FK не даёт физически удалить ингредиент).

Не реализовано: экраны каталога, дневник (N02), цели (N03), статистика питания (N04),
вода, участник окончательного удаления клиента (каталог не клиентский), миграция build120.
