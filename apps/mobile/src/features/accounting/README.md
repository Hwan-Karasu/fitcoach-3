# SessionAccounting

Тарифы услуг, пакеты занятий, Payment Ledger и Credit Ledger. Факты кредитов
не выводятся из статуса тренировки и не сводятся к изменяемому `pack.used`.

Dev-only вертикальный срез L01 (`data/DevAccountingRepository.ts`) живёт в общем
dev-файле с Clients и Calendar, журнал миграций `accounting_schema_migrations`.

- Режим учёта клиента `FITCOACH | EXTERNAL | UNTRACKED`; по умолчанию для
  workspace — `UNTRACKED`, у клиента может быть свой. Только `FITCOACH` трогает
  Credit Ledger; отсутствие пакета не блокирует Calendar.
- Пакет начисляет `ISSUED +N` в той же транзакции; условия хранятся snapshot.
  Credit scope `GENERAL` или `SESSION_TYPE` (только платный тип занятия).
- Credit Ledger только дополняется: триггеры запрещают UPDATE и DELETE, кроме
  окончательного удаления клиента. Остаток = сумма журнала − резервы.
- `devAccountingCalendarHook` выполняется внутри транзакции Calendar: резерв при
  записи, перенос резерва вместе с ID, возврат/списание при удалении записи,
  только освобождение при Clear Week, пересчёт при Paste Week без наследования
  «без списания».
- `reconcileDue` идемпотентно превращает резерв закончившейся записи в один
  `USED -1`; вызывается при запуске, возобновлении и раз в минуту.
- Исход записи (L02): Завершена/Пропущена через `settle` дают ровно один
  `USED`, Отменена — связанный `RETURNED`; `correct` компенсирует прежнего
  клиента и списывает у нового в той же транзакции Calendar.
- Оплаты — отдельные ручные записи в копейках, без связи с кредитами.

Не реализовано: шаблоны тарифов, системное уведомление о списании (N04),
workspace default в настройках, ручные корректировки в UI.
