# Measurements

Измерения с устойчивыми ID и датой/временем, выбор primary/day measurement.
Вес не дублируется как изменяемое поле basic profile.

Dev-only вертикальный срез C06 (`data/DevMeasurementRepository.ts`) живёт в общем
dev-файле с Clients, журнал миграций `measurement_schema_migrations`.

- Фиксированный набор §49.14: масса, процент жира и восемь обхватов; значения
  хранятся в десятых (`80,1 кг` → 801), отсутствующий замер — «нет данных».
- Каждая запись — отдельный факт (§49.15): несколько за день, исправление и
  удаление конкретной записи по revision; время может быть неизвестно
  (`localMinute = null`) — фиктивное время не придумывается.
- Основной замер (§49.18) — на пару `тип + дата`; составной FK не даёт отметить
  чужой тип/дату. Без выбора при нескольких записях дневная точка `AMBIGUOUS`,
  без среднего и без «последнего»; удаление основного не повышает другой.
- `devMeasurementClientDeletionParticipant` подключается к окончательному
  удалению клиента.

Не реализовано: графики и статистика питания, калькулятор ВМС США (§49.16),
вес из формы клиента (§10.13.1), текущий вес на Главной (C05), миграция build120.
